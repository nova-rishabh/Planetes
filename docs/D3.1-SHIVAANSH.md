# D3.1 — Resolve and propagate astronomical targets

**Owner:** Shivaansh  
**Owned implementation:** `pipeline/src/planetes/resolve.py`

## Scope

D3.1 resolves a target name or decimal-degree `RA, Dec` input to an ICRS
position and available astrometry, then propagates that position to any
Modified Julian Date (MJD).

The public entry points are:

- `resolve(query) -> Astrometry`
- `Astrometry.position_at(mjd) -> SkyCoord`
- `position_at(target, mjd) -> SkyCoord`
- `resolve_response(query) -> Resolved` (the generated API contract model)

## Data flow

1. For a name, SIMBAD resolves the object identity and supplies an initial
   position plus any available proper motion, parallax and coordinate epoch.
2. If SIMBAD supplies proper motion and an epoch, the resolver propagates the
   cross-match centre to Gaia DR3's reference epoch (2016.0). This matters for
   high-proper-motion stars.
3. The code inspects the live Gaia DR3 table metadata before using its TAP
   columns, then searches within 30 arcseconds and selects the nearest source.
4. If Gaia matches, its RA/Dec, `pmra`, `pmdec`, parallax and `ref_epoch` are
   used together. Gaia coordinates are not mixed with an older SIMBAD epoch.
5. If Gaia does not match, available SIMBAD values are retained. Missing values
   remain `None`; no default epoch or zero proper motion is fabricated.
6. `position_at(mjd)` uses Astropy `SkyCoord.apply_space_motion`.

For coordinate input, RA and Dec are accepted in decimal degrees as
`"RA, Dec"` and Gaia is queried for enrichment. If no catalog astrometry is
available, the input coordinate is retained, but propagation correctly
raises because its epoch and motion are unknown.

## Units and conventions

- `ra_deg`, `dec_deg`: ICRS degrees.
- `pm_ra_masyr`, `pm_dec_masyr`: milliarcseconds/year.
- `parallax_mas`: milliarcseconds.
- `ref_epoch_jyear`: Julian year.
- `mjd`: Modified Julian Date, days.
- Gaia DR3 `pmra` is μα*cos(δ). It is passed to Astropy as
  `pm_ra_cosdec`; **do not multiply by cos(dec) a second time**.
- Positive parallax is converted to distance for perspective effects. Missing
  or non-positive parallax is not turned into an invented distance.

## Five official benchmark targets

The IDs and names are taken from `web/src/lib/benchmarks.ts` and
`docs/04-Science-Validation.md`:

| ID | Target |
|---|---|
| `barnard` | Barnard's Star |
| `wise0855` | WISE 0855−0714 |
| `epsindib` | ε Indi Ba/Bb |
| `rwaur` | RW Aurigae |
| `rdra` | R Draconis |

The resolver fetches catalog values at runtime; it does not hard-code
positions or motions into production code. Live network tests check that all
five names resolve.

```bash
pytest -q tests/test_resolve.py -m network
ruff check src/planetes/resolve.py tests/test_resolve.py
ruff format --check src/planetes/resolve.py tests/test_resolve.py
```

Network tests require access to CDS SIMBAD and the ESA Gaia Archive.

## Acceptance test still requiring SPHEREx evidence

The role guide's D3.1 acceptance criterion is that Barnard's Star lands within
2 arcseconds of its position in a real 2026 SPHEREx frame. The resolver
provides the propagated coordinate, but this is an end-to-end check: it must
be compared with a real frame's WCS and the frame's MJD. Tirth's frame list /
frame product is needed for that check. No pass is claimed in this PR until
that real comparison has been run.
